# Decision Log

Settled product and architecture decisions. Newest first within each group. When a decision
changes, update this file, `project-description.md` and `build-plan.md` together.

## Product

| Decision                  | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Push message approval     | Publishing drafts a `push_messages` row (copy + optional `send_at`). Inbox rows and Expo pushes happen only when a worker sends an approved due message. Trusted publishers (`verified`) and imported `auto_publish` mapped publishers auto-approve; others need admin approval. Edits before send update the open draft (untrusted edits re-pend approval). After send, publishers may create a new draft (“Notify again”). Admins can also schedule **broadcasts** (`kind=broadcast`, no event): audience `everyone` or `tag_interest` (users with that tag in `user_interests`). Broadcasts are approved on create. Per-user aggregation: if another matching approved message is due within 10 minutes, defer and combine into one silent push (earliest copy + “And N more…”). Admin editor shows estimated audience. |
| Optional check-in         | Check-in is off until an admin enables it on that event. When it is on, the publisher can add extra text and links that attendees see only after they check in. Imports do not change the flag or that text. Ratings still require a check-in, so an event with check-in off cannot be rated.                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Featured events           | Admins can mark an event `featured`. Published featured events sort first on the public list and the home page. The flag is not part of an import, so a later sync does not clear it. Paid `featured_placements` (slot, area, dates, plan quota) stay a future feature.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Event tags                | Events use a flat tag list instead of the old category tree. The launch vocabulary is Visit Söderhamn categories under Evenemang (Citybreak id 30172), stored in `tags` with `external_id` `visit-soderhamn:{id}`. A live import upserts the rest of that tree. Publishers and admins pick those tags. User notification interests are tag ids. Existing interests are cleared because the old category ids do not map. Home chips for all / in person / online stay mode filters. Tag names are the Swedish source names until they are translated. |
| Event links and price     | Tickets and registration are links on the event (`tickets`, `registration`, `info`), not separate records. An event can have several. Imports from every source keep adapter links and also add http(s) links parsed from the description. `onlineUrl` stays the place a digital event happens. Price is optional minor units (`null` unknown, `0` free) plus a currency, default SEK. The public list treats unknown the same as free. Visit Söderhamn sets that amount only when the description says gratis or states a price in kr.                                                                                                                                                                                                                                                                                                                                                                                         |
| Saved events and lists    | A save is a row in `saved_events`, separate from notification follows. Users can also keep up to 20 named lists. Both are stored for the device user and removed with that user.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Event location            | A physical event may omit its point. It still appears in the event list. It has no map pin and does not match nearby push. Digital events still need an online URL.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Business model            | Free for users, funded by ads. v1: everyone publishes for free; no subscription option anywhere. Paid publisher plans (Free/Small/Medium/Large) are a future feature; only entitlement checks exist in code.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Region subscriptions      | When the app is actively used somewhere new, offer to save the place as a region and notify about events there. Runs on device; nothing sent unless saved.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Launch area and languages | Söderhamn and Gävleborgs län; Swedish (default) and English.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Publisher members         | Owner and editor roles in v1.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Ratings visibility        | Public sees only aggregate (average + count). Anonymous users can rate but not comment. Comments visible to publisher and admins only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Identity recovery         | Device linking via pairing code + optional recovery email, both in v1.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Imported events           | Per-source trust level; new sources start in review. Unknown organizers get a temporary publisher that admins re-map or complete.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| First data source         | Visit Söderhamn (Citybreak CBIS). Import category 30172 Evenemang only, one event per occasion. API key is `VISIT_SODERHAMN_API_KEY`, not stored in config. Trust stays `review`. Additional calendars use the generic `ics-feed` adapter (`config.feedUrl`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Who can publish           | Anyone can register; events from unverified publishers stay hidden and are never pushed until an admin verifies the publisher. Upcoming events are then released; ended ones stay hidden.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Users                     | Anonymous by default, no registration. Profile (name or anonymous) offered at first check-in. Web login only for publishers or app users pairing via code.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Nearby push rules         | Match active notify areas (circle `ST_DWithin` / polygon `ST_Covers`) ∩ interest overlap (empty interests = no nearby match). Audience is resolved at **send** time from an approved `push_messages` row (not at publish). Insert a `notifications` inbox row per match then; silent/data Expo push when a device token exists (may be aggregated per user within 10 minutes). Quiet hours (default 22:00–08:00 `Europe/Stockholm`, editable in preferences) and the 5/day cap are **client-only**. Listing and unread badge are API-backed (`GET /me/notifications`). Inbox rows older than 90 days are purged by the worker. Events without a point skip nearby but still notify publisher followers. Fan-out capped at 500 candidates per path per message. |

## Architecture

| Decision     | Detail                                                                                                                                                                                                                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Event share links | Mobile share uses the OS share sheet with an HTTPS link to the public web event page (`EXPO_PUBLIC_WEB_URL/events/{id}`). Universal Links (iOS) and App Links (Android) open that URL in the app when installed; otherwise the web page loads. Association files are served from `apps/web` `/.well-known/*` when `APPLE_TEAM_ID` / `ANDROID_SHA256_CERT_FINGERPRINTS` are set. |
| API style    | REST + OpenAPI (Zod-first via @hono/zod-openapi) for both public and admin APIs.                                                                                                                                                                                                                            |
| Auth         | Own auth in the APIs, users/devices/sessions in Postgres. No Cognito. App stores a random device credential in secure storage; a user id alone never authenticates.                                                                                                                                         |
| Data workers | Part of the monorepo (`apps/data-workers`); one adapter per source; scheduled Fargate tasks (~0.25 vCPU / 0.5 GB).                                                                                                                                                                                          |
| Hosting      | AWS, eu-north-1 (Stockholm), dev/staging/prod accounts, CDK.                                                                                                                                                                                                                                                |
| UI kit       | Material UI (`@mui/material` + `@mui/material-nextjs`) on `apps/web` and `apps/admin`. Mobile uses custom RN screens plus `@expo/ui` (universal BottomSheet/etc.) and SwiftUI overlays (`ConfirmationDialog`, `ContextMenu`, `DatePicker`, `Alert`) for system chrome — not React Native Paper / Gluestack. |
| Monorepo     | pnpm workspaces + Turborepo; Expo (mobile), Next.js (web, admin).                                                                                                                                                                                                                                           |
| Database     | PostgreSQL + PostGIS on RDS; Drizzle ORM. Geography columns are plain `geography` because drizzle-kit quotes constrained type names.                                                                                                                                                                        |
| Local queues | ElasticMQ in Docker Compose as the SQS stand-in (`domain-events` + DLQ). Same `@aws-sdk/client-sqs` clients; `AWS_ENDPOINT_URL_SQS` + `DOMAIN_EVENTS_QUEUE_URL` point at localhost. Real SQS in AWS.                                                                                                        |
| Event images | Public heroes live in `event_images` (role `main`, key `events/{eventId}/main`). Local Garage bucket `local-events-assets` (S3 API `:3900`, website `http://local-events-assets.localhost:3902`). AWS: the public-assets bucket stays private behind CloudFront with origin access control. The API returns `imageUrl` from `ASSETS_PUBLIC_BASE_URL` plus the key. Import copies the source image best-effort and does not fail the event. Attendee files stay on the private bucket. |

## Risk mitigations (reviewed, kept as proposed)

Too few events at launch · source breakage/scraping · duplicate imports · cheap anonymous identities
(device attestation stays v2) · indoor GPS · notification fatigue · app store location review ·
digital code sharing. See `project-description.md` → Risks.
